## Introduction

Atelier UI is a React component library built from scratch, accompanied by an interactive demo site. Written in TypeScript, it provides separate styles and import paths for individual components. The documentation site includes interactive examples, complete code samples, and API references.

Welcome to Atelier UI. Explore component interactions in the live documentation, inspect the full example code, and bring the components you need into your own project. Whether you are building an interface or looking up a component API, the catalog below is a starting point.

Design tokens and cross-framework component contracts are documented in the design system specification: [English](./DESIGN_SYSTEM.md) · [中文](./DESIGN_SYSTEM.zh-CN.md). Machine-readable tokens are available in [`design-tokens.json`](./design-tokens.json).

The project uses a single npm package without npm workspaces:

- `src/`: component source code, form Hooks, and component styles.
- `demo/`: component documentation and interactive examples.
- `docs/`: GitHub Pages output generated by production builds.

### Global Configuration and Utilities

`ConfigProvider` configures component prefixes, direction, size, locale, and theme variables; `useConfig` reads the configuration. Public utilities include `formatTime`, `parseTime`, `formatCountdown`, `formatStatistic`, `hsvToRgb`, `parseColor`, `rgbToHsv`, and `toHex`.


### Light and Dark Themes

The documentation site's upper-right sun/moon button switches between light and dark mode. The first visit follows the system preference; a manual selection is remembered in local storage. Language, the current page and form state are preserved when switching.

```tsx
import { ConfigProvider } from 'atelier-ui/config-provider';
import { Button } from 'atelier-ui/button';

export function ThemeExample() {
  return (
    <ConfigProvider colorScheme="dark">
      <Button variant="primary">Dark theme</Button>
      <ConfigProvider colorScheme="light"><Button>Light section</Button></ConfigProvider>
    </ConfigProvider>
  );
}
```

`colorScheme` inherits from the parent provider. Without an explicit scheme, components inherit the surrounding CSS theme, which defaults to light. For an entire application, set `data-at-theme="dark"` or `data-at-theme="light"` on the document root. Popups and dialogs preserve an explicit provider scheme. Bound `useModal`, `useMessage` and `useNotification` APIs pass it to standalone overlays; unbound APIs can receive a `colorScheme` option. Explicit theme tokens still take priority. Intrinsic image, QR-code and color-picker colors remain unchanged.

### Internationalization

All built-in component text and accessible labels support Simplified Chinese and English. The default is `zh-CN`. Components without built-in text continue to render the content you supply. Explicit text props take precedence, including an intentional empty string or `null` where the prop permits it.

```tsx
import { ConfigProvider } from 'atelier-ui/config-provider';
import { createLocale, enUS } from 'atelier-ui/locale';
import { Empty } from 'atelier-ui/empty';

const jaJP = createLocale('ja-JP', {
  'common.noData': 'データがありません',
  'common.ok': '確認',
}, enUS);

export function Example() {
  return (
    <ConfigProvider locale="en-US" locales={{ 'ja-JP': jaJP }}>
      <Empty />
      <ConfigProvider messages={{ 'common.noData': 'Nothing here yet' }}>
        <Empty />
      </ConfigProvider>
      <ConfigProvider locale="ja-JP"><Empty /></ConfigProvider>
    </ConfigProvider>
  );
}
```

- `locale`: a language identifier or a `Locale` object such as `enUS` or `zhCN`.
- `locales`: register additional packs by identifier. `createLocale(code, messages, base = enUS, formatLocale = code)` fills missing translations from the base. Unsupported Intl identifiers use the base formatting locale.
- `messages`: typed partial overrides for the selected pack. Nested providers inherit the parent language, registry and configuration unless overridden.
- `useLocale()`: read `locale`, `formatLocale`, `messages` and `t(key, params)`. Message keys and interpolation parameters are documented by the exported `LocaleKey`, `LocaleMessages` and `LocaleParams` types. For example, `t('pagination.total', { total: 12 })`.

Dates, calendar month/weekday names, default numeric separators, number tickers and table sorting use the formatting locale. Existing formatting props still override the defaults. Native date-picker UI also depends on the browser and operating system. User-provided labels, content, validation messages and schema errors remain under application control.

Standalone APIs render outside the calling React tree. Use `useModal()`, `useMessage()` and `useNotification()` inside a provider to create language-bound APIs. Alternatively pass `locale: enUS` in `Modal.confirm`, message options or notification options. Unbound static APIs keep the default Chinese locale. The optional second argument to `yupResolver(schema, locale)` controls its built-in fallback message; schema-provided errors are preserved.

The documentation language switch is in the upper-right corner. It updates navigation, descriptions, API tables, examples and the surrounding ConfigProvider, remembers the choice in local storage, and preserves the current page and form state. Component-language controls on the ConfigProvider page can intentionally override the site language.

### Form Hooks

The form API manages state through `useForm`, `useWatch`, `Controller`, `FormProvider`, `useFormContext`, and `useFieldArray`, with optional Zod and Yup resolvers. Form state is managed through Hooks; the library does not provide `<Form>` or `<Form.Item>` components.

## Local Development

Requires Node.js `>=20.19.0`.

```bash
npm install
npm run dev
```

The development server prints its local URL in the terminal.

Unit tests use Vitest, React Testing Library, and jsdom. They do not require a running demo or an installed browser:

```bash
npm test                 # Run all unit tests once
npm run test:watch       # Watch for changes during development
npm run test:coverage    # Check coverage and generate coverage/index.html
```

Tests live in `tests/unit/` and cover component state, interactions, keyboard behavior, form Hooks and validation, utilities, animation timers, and cleanup. Coverage includes all components and internal logic, excluding re-export entry points and type declarations. Minimum thresholds are 80% statements, 70% branches, 80% functions, and 85% lines. Tests supply mocks for geometry, Canvas, and browser observers where needed; Playwright UI tests verify actual layout and styles.

Before running UI tests for the first time, install Playwright Chromium:

```bash
npx playwright install chromium
npm run test:ui
```

UI tests build the production demo and check component styles, documentation navigation, and key Rate and Transfer interactions.

## Build and Checks

```bash
npm test
npm run typecheck
npm run build
```

`npm run build` outputs the component library to `dist/` and the demo site to `docs/`. After pushing the `master` branch, GitHub Pages serves the site from `master /docs`.

Available scripts:

| Command | Purpose |

## Component Imports

Each component has a separate entry point that automatically imports its CSS. With a build tool that supports CSS imports, such as Vite, webpack, or Rspack, import components as needed:

```tsx
import { Button } from 'atelier-ui/button';
import { Table } from 'atelier-ui/table';
import { useForm } from 'atelier-ui/form';
```

The package also provides a root entry point for importing multiple modules together. Separate entry points let you import only the components and styles you need.

> This project has not yet been published to the npm registry. The package name and export paths in `package.json` support local builds and preparation for a future release.
